# Transformers 5.2+ dependency update (ROCm MI50/gfx906)

## Scope
This update changes dependency declarations only (no Dockerfile or runtime code refactors) to enable Transformers 5.2+ compatibility while keeping ROCm/gfx906 install posture intact.

## Exact files and lines changed

1. `requirements/common.txt`
   - Line 10: `transformers >= 4.56.0, < 5` -> `transformers >= 5.2, < 6`
   - Line 11: `tokenizers >= 0.21.1` -> `tokenizers >= 0.22.0, < 0.23`
   - Line 12 (added): `huggingface-hub >= 0.34.0, < 1.0`
   - Line 13 (added): `safetensors >= 0.4.5`

2. `requirements/test.in`
   - Line 40: `transformers==4.57.3` -> `transformers>=5.2,<6`
   - Line 41: `tokenizers==0.22.0` -> `tokenizers>=0.22.0,<0.23`

3. `requirements/nightly_torch_test.txt`
   - Line 32: `transformers==4.57.3` -> `transformers>=5.2,<6`
   - Line 33: `tokenizers==0.22.0` -> `tokenizers>=0.22.0,<0.23`

4. `requirements/test.txt`
   - Line 1199: `transformers==4.57.3` -> `transformers>=5.2,<6`

## Rationale per dependency adjustment

- `transformers >= 5.2, < 6`
  - Moves the project to the requested major line and prevents unbounded major-version breakage.
  - Applied in shared runtime deps and test deps so install and CI expectations stay aligned.

- `tokenizers >= 0.22.0, < 0.23`
  - Aligns tokenizer floor with current Transformers 5.x era packaging.
  - Keeps a conservative upper bound to reduce sudden ABI/API shifts.

- `huggingface-hub >= 0.34.0, < 1.0`
  - Added explicitly to avoid relying on transitive resolution behavior.
  - Pre-1.0 cap keeps compatibility with existing integration assumptions.

- `safetensors >= 0.4.5`
  - Added explicitly to ensure modern safe weight-loading paths expected by current Transformers releases.

## ROCm MI50/gfx906 compatibility caveats

- No CUDA-only dependencies were introduced in this update.
- Existing ROCm build/install files and patterns were preserved:
  - `requirements/rocm.txt` unchanged.
  - `requirements/rocm-build.txt` unchanged.
- Practical risk remains that some model-side features in the Transformers 5.x ecosystem can assume newer kernels/toolchains than MI50/gfx906 supports; this is runtime-model-specific rather than dependency-declaration-specific.
- `requirements/test.txt` is an autogenerated lock-style file and now includes a range for `transformers`; a follow-up lock regeneration (`uv pip compile`) is recommended in CI to fully normalize resolved pins per backend/profile.
